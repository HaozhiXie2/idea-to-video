# Internal API contract (v1)

## Confirmed flow update (2026-09-24; overrides old descriptions below)

UI has THREE main workspaces: 定方案 / 定形象 / 做成片. This does NOT mean only three clicks: approvals and paid confirmations remain explicit.

- `/analyze` additionally takes `stage:"plan"|"assets"|"storyboard"`. Defaults to `plan`. Plan only returns plan/questions, NEVER assets/shots; asks purpose/audience/style/content choices, NOT costume/face yet. Assets requires approved plan; asks missing appearance/product details and returns assets only. Storyboard requires approved assets; returns shots only (5/10 sec sum exact). `questions_stage` identifies current question round; question IDs namespaced by stage and round internally; frontend submit current questions' exact IDs. `planning_stage` indicates completed stage (null/plan/assets/storyboard). A request may return grouped questions instead of stage content. Text service still configurable/unconfigured honest. Explicit analysis invocation explains possible text fees. Failed stage calls retain previous content.
- Plan can include `beats:[{title,content,source_excerpt}]` (optional); summary/style/audience/creative_notes remain. Different templates use different outline, not forced one-scene drama. Silent visual storytelling only, no spoken dialogue requirement.
- Asset `type` and `reference_role` additionally allow `style`; style sample is OPTIONAL. A user may upload style reference or reuse an approved scene/other asset. No compulsory extra paid style image. API `/style-reference` `{expected_revision,asset_id:null|id}` marks selected approved asset as common style reference, or clears it. Project `style_asset_id` stores choice. This invalidates dependent storyboard images; all future shot image prompts actually carry this reference and label its role. UI exposes checkbox/select “同时用作风格参考” on approved image. Body/face references separate, no contact sheets.
- `/approve` stage `assets` requires `planning_stage` assets/storyboard, all required assets approved, and sets phase storyboard; UI THEN invokes analyze stage storyboard. `/approve` stage storyboard still requires all current images, and moves into video trial.
- Project `trial:{shot_id:null|id,version_id:null|id,approved:false}`. `/trial` `{expected_revision,shot_id}` chooses a real shot after storyboard approval. 5s preferred but actual chosen shot duration (5 or10) is used. Prior to trial approval, shot_video quote MUST be exactly this one chosen shot; no other video generation permitted. `/approve` stage `motion` approves CURRENT selected done video for trial shot; it must be nonstale. This trial is reusable as final footage; default remaining-batch selection excludes done videos. Trial approval only valid while chosen trial image/video & prompts unchanged. Other unrelated shot edits keep trial approval, but storyboard may require reapproval. Changing trial or affecting it revokes motion approval.
- Project `batch_limit` defaults3. `/settings` `{expected_revision,batch_limit:1..18}` adjusts per-batch cap. quote rejects count>batch_limit, no silent truncation. Single asset candidate rule still applies. Query errors/uncertain tasks stop further spending; failed task pauses its project's remaining queue. `/pause` also accepts `cancel_queued:true` to cancel only unsent jobs and allow editing; running task never claimed canceled/refunded.
- Motion-only edit keeps shot image valid and storyboard approval; only video stale. Asset/appearance/composition edits invalidate affected static images. Duration and ref mapping remain unchanged in text edit. User may add a new costume/scene via explicit `/asset-variant` `{expected_revision,asset_id,name,description,prompt,shot_ids:[...]}`; creates NEW asset record with no media, changes refs only in selected shots, preserves old images/identity (all fields explicit user authored). Later restoring a version is manual and never auto spends.
- `/restore` restores content snapshot but trial approval resets. Restore retains job ledger and every media version, including newer ones for comparison. `planning_stage`, `style_asset_id`, `trial`, `batch_limit` persisted. No automatic paid calls in test/deploy.

Loopback only, `127.0.0.1:7862`. JSON requests and responses. Errors `{error:string}`. Every POST requires `X-Studio-Token` from HTML meta `studio-token` injected as `__TOKEN__`. All user-visible strings are Chinese. Static files `/app.js`, `/style.css`. No key ever appears in responses.

GET `/api/status` -> `{app:"idea-to-video",version:1,cli_available,ffmpeg_available,text_configured}`.
GET `/api/config` -> `{base_url,model,key_configured,json_mode}`; POST `/api/config` with `{base_url,model,api_key?,clear_key?,json_mode}` (blank key preserves previous). Endpoints require HTTPS except localhost. No auto connection check or paid calls.
GET `/api/projects` -> project summaries `{id,title,template,duration,ratio,updated,phase}` array.
POST `/api/projects` -> project, body `{title?,source,template:"story"|"product"|"knowledge"|"memory",duration:15|30|60|90,ratio:"9:16"|"16:9"|"1:1"}`. No cloud calls. Source max 60000 chars. TXT/MD upload read by browser into source field.
GET `/api/projects/<id>` -> project (defined below).
POST `/api/projects/<id>/analyze` `{expected_revision,answers?:{question_id:answer}}`: calls configured text provider once, may take 120s. Consent via UI: input/answers sent to provider, may incur text fees. Unconfigured returns error. Never fabricates demo data. Returns updated project (questions OR valid plan/assets/shots). No generation until questions resolved. Repeat analysis only before plan approval.
POST `/api/projects/<id>/approve` `{expected_revision,stage:"plan"|"assets"|"storyboard"}` -> project. Plan requires no questions; assets requires approved version for every asset (empty assets is valid); storyboard requires every shot's current non-stale image version.
POST `/api/projects/<id>/upload` `{expected_revision,asset_id,data:base64,name:string}` -> project. PNG/JPEG/WebP max 8MB. One candidate version, not auto-approved. Uploaded material stays local until referenced in a generation.
POST `/api/projects/<id>/select` `{expected_revision,entity:"asset"|"shot",entity_id,kind:"image"|"video",version_id}` -> project. Selecting/restoring a different asset invalidates only dependent shots. Selecting shot image invalidates its video. No billing. Asset selected version marks approved=true.
POST `/api/projects/<id>/quote` `{kind:"asset_image"|"shot_image"|"shot_video",entity_ids:[...]}` -> `{quote_id,count,kind,items:[{entity_id,label}],cost_known:false,warning,revision}`. A quote freezes prompts/settings/references. Empty IDs means all needing work. Candidate asset batch MUST contain exactly one asset. Same-kind queued/uncertain job blocks more for that entity. Backend gates approvals.
POST `/api/projects/<id>/generate` `{quote_id,confirmed:true,request_id:UUID}` -> `{batch_id,jobs:[...],project}`. Generates only approved quote, no hidden retries. Queue is sequential and may pause. Double click with same request ID returns original batch; quote may be used only once. Real generation requires explicit count+unknown-cost confirmation. Returns immediately.
POST `/api/projects/<id>/pause` `{paused:boolean}` -> project. Pause stops FUTURE submissions, not running remote jobs.
POST `/api/projects/<id>/recover` `{job_id,submit_id?:string}` -> project. Query existing remote task only. A user may bind a manually verified UUID task ID to an uncertain job. No new submit.
POST `/api/projects/<id>/edit-proposal` `{expected_revision,target:"shot"|"asset",target_id,instruction}` -> `{proposal_id,summary,changes,affected_shots,revision}`. One cloud text call; asks questions via error if unclear. Structured new fields only, no media generation. Shot changes can edit description/camera/action/image_prompt/video_prompt; asset changes description/prompt. Duration stays unchanged. Missing creative info must be asked, never filled silently.
POST `/api/projects/<id>/apply-edit` `{expected_revision,proposal_id}` -> project. Archives full snapshot, invalidates only affected outputs. Removes affected approvals. No paid generation.
POST `/api/projects/<id>/restore` `{expected_revision,version_id}` -> project. Restore prior full content snapshot, keeps job ledger and media files; restored approvals reset so user checks them again; old versions not deleted.
POST `/api/projects/<id>/remove-shot` `{expected_revision,shot_id}` -> project. Blocks active jobs; explicit UI confirms shortened total duration. No billing.
POST `/api/projects/<id>/export` `{expected_revision,kind:"draft"|"final"}` -> `{export_id,status:"queued"}`. Local async FFmpeg. Draft requires all current images and outputs CLEARLY marked static draft. Final requires storyboard approved + all current videos; silent MP4. Status/result appears in project's exports. No cloud calls.
GET `/media/<project>/<relative-file>` -> allowlisted project media only (not project JSON/config), HEAD/ranges supported. Frontend uses `url` on version, never guesses local paths.

Project shape:
```
{id,title,source,template,duration,ratio,revision,phase,created,updated,
 answers:{},questions:[{id,question,options?:[]}],
 plan:null|{summary,style,audience,creative_notes:[string]},
 approvals:{plan:false,assets:false,storyboard:false},
 assets:[{id,type:"character"|"product"|"scene",name,description,prompt,reference_role:"face"|"full_body"|"product"|"scene",selected_image:null|versionId,approved:false,versions:[]}],
 shots:[{id,title,source_excerpt,description,camera,action,duration:5|10,asset_ids:[],image_prompt,video_prompt,selected_image:null|versionId,selected_video:null|versionId,image_stale:true,video_stale:true,versions:[]}],
 jobs:[{id,project_id,entity_id,kind,status,message,submit_id?,created,images:[],videos:[],url?,query_error?}],
 paused:false,history:[{id,label,created}],exports:[{id,kind,status,url?,message,revision}],
 text_status?:"analyzing"|"idle",text_error?:string}
```
Version: `{id,kind:"image"|"video",url,created,prompt,job_id?,label}`. UI may compare thumbnails/videos+prompt side-by-side. History is project snapshot history, `/restore` restores entire content. `phase`: idea/questions/plan/assets/storyboard/video/complete. Show actual jobs without fabricated progress/ETAs.

## Media adapter contract (Python module app/media.py)

`MediaEngine(root:Path)` with `available()->bool`, `ffmpeg_available()->bool`, `submit(spec:dict, directory:Path)->dict`, `query(submit_id:str,directory:Path,kind:str)->dict`, `export(clips:list[dict],destination:Path,ratio:str,draft:bool)->Path`.

Submit spec: `{kind:"image"|"video",prompt,ratio,model,duration?,references:[absolute-local-Path-strings]}`. Inputs are resolved and validated by server. Image reference calls image2image (no refs text2image); video exactly one shot image reference image2video. CLI path root/.tools/dreamina.exe. Config/login home root/.local/dreamina-home (independent, no old credential copying); ensure CLI env isolates home. Return `{submit_id,credits?}`; errors raise MediaError(message, uncertain:bool) default uncertain for timeout/unparseable/no-id after attempted paid submission. No retries. Query ONLY query_result optionally download; return `{status:"waiting"|"done"|"failed",message,files:[Path strings],credits?}`, backend copies no external paths. Use strict extension/local output allowlist. Export clips `{path:Path,duration:5|10}`. Draft uses still images; final trims (never loops a too-short video) and removes all audio; maintain portrait output720x1280 or landscape1280x720/square720. Use own imageio_ffmpeg installed dependency for executable, not old repo.

Main backend owns persisted state/idempotency/snapshots/worker; media adapter does not keep jobs. Agent writing media owns app/media.py + tests/test_media.py only. Frontend agent owns app/index.html/app.js/style.css + tests/test_ui.cjs only. Docs/setup agent owns README/LICENSE/.gitignore/docs (except API.md)/scripts/.github/Start-Studio.cmd/requirements.txt only. Main owns all remaining app/test files.
